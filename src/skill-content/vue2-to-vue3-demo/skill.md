- 自动过滤无用 mixins、公共方法、变量

- 第三方依赖升级为 Vue3 版本

- 后端数据统一 mock

- 样式优先截图，其次源码样式，其余用 Tailwind CSS

- 最终生成可运行 Demo 页面，让原 Vue2 公共组件在 Vue3 中 可展示、可交互、可演示

## 核心原则

1. Vue2 源码 **仅作为参考素材，不可运行**

2. 页面截图 > Vue2 样式代码

3. 尽量复用提供的 mixins/公共方法，但缺失或未用到的自动过滤

4. 第三方 npm 包必须升级到 Vue3 版本

5. 后端数据一律 mock

6. 最终组件可运行、交互完整、视觉接近截图

## 输入内容（你将收到）

1. **一个已抽离的文件夹**
   
   - 来自 Vue2 老项目的公共组件
   
   - 包含：
     
     - 主组件
     
     - 子组件
     
     - 样式文件
     
     - mixins / 公共方法（可能冗余、缺失、不完整）
   
   - ❗该文件夹本身 **无法运行**

2. **组件页面截图文件夹componentImage**
   
   - 包含 1 张或多张页面截图
   
   - 用于样式还原与布局判断

3. （可选）组件中引用的第三方库线索

## 你必须遵循的整体流程

### 一、项目初始化（必须你来做）

你需要**直接构建一个全新的 Vue3 项目**，而不是基于已有项目修改：

- 技术栈固定：
  
  - Vue 3
  
  - TypeScript
  
  - Vite
  
  - Tailwind CSS

- 项目需支持：
  
  - `npm install`
  
  - `npm run dev`

- 目录结构需规范、清晰、可维护

---

### 二、组件扫描与迁移

- **扫描并分析**我提供的抽离文件夹

- 找出：
  
  - 实际被使用的组件
  
  - 实际被使用的 methods / mixins / 变量

- ❗**未被使用的代码必须过滤删除**

- 将有效代码迁移进 Vue3 项目中：
  
  - Vue2 Options API → Vue3 Composition API（优先）
  
  - 必要时可保留 Options API，但不推荐

- 带插槽的骨架样式组件base-wrapper，直接忽略不用管

- 图片上传公共组件，没有办法给你阿里云oss，你可以做个假的，点击上传后在页面显示就行

- 表格组件使用element-plus的

- 去除页面所有的v-permissions以及v-dialogDrag这种无效自定义指令

---

### 三、第三方依赖处理

- 如果组件依赖第三方 npm 包：
  
  - 你必须 **联网查找 Vue3 兼容版本**
  
  - 替换 Vue2 不可用版本

- 若存在：
  
  - Vue2 专属库
  
  - 已废弃库  
    → 请用 Vue3 等价方案替代

---

### 四、样式处理规则（重点）

1. **优先级规则**
   
   - 有原样式 → 尽量迁移
   
   - 没有样式 / 样式缺失 → 使用 **Tailwind CSS 重写**

2. **页面截图是最高参考标准**
   
   - 必须结合截图分析：
     
     - 布局结构
     
     - 间距
     
     - 排版
     
     - 主视觉层级
   
   - 不要求像素级一致，但：
     
     - 结构必须一致
     
     - 使用场景必须合理

3. 路径别名：
   
   - 使用 `@/` 作为统一路径规范

---

### 五、数据源与 Mock 规则

- 若发现组件依赖后端数据：
  
  - **一律 Mock**

- Mock 方式：
  
  - 本地静态数据
  
  - 或简单封装请求模拟

- Mock 数据需：
  
  - 符合真实业务结构
  
  - 支持页面完整渲染与交互

---

### 六、路由处理规则

- 若组件包含 router：
  
  - 使用 **Vue Router 4**

- 原 Vue2 项目中的：
  
  - 首页
  
  - 业务跳转页

- 在 Demo 中：
  
  - **不需要真实业务页面**
  
  - 可跳转至：
    
    - demo 页面
    
    - 占位页面
    
    - 或直接取消跳转逻辑

---

### 七、mixins / 全局方法处理

- 若我提供了 mixins / 公共方法：
  
  - 你需要判断：
    
    - 是否真的被该组件使用

- 未使用的：
  
  - **直接删除**

- 使用的：
  
  - 重构为：
    
    - `composables`
    
    - 或普通工具函数

---
